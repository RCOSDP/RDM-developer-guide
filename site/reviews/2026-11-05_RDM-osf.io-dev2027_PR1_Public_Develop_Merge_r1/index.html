    English¶

    Verdict: request changes¶

    Reviewed repository RCOSDP/RDM-osf.io-dev2027, PR #1, head 546969eb33f42e35be5dc5c5ac8bfe55e3ef0bbc. This is a review recommendation, not a submitted approval or merge. No production-code regression or loss of private hardening was found in the two-file delta. Resolve R1 and R2 before merging; R3 is an owner disclosure decision.

    Findings, ranked by severity¶

    1. R1 — Medium (P2): the new anonymous API 2.10 test supplies authentication. At head, api_tests/users/views/test_user_detail.py:260–262, test_social_values_old_version_not_logged_in passes auth=user_one while expecting 401. The same test's 2.9 request at lines 256–258 omits authentication; successful authenticated requests at lines 234–248 use user_one.auth. Consequently the 2.10 case is not a clean test of absent credentials: rejection of the supplied authentication can satisfy the assertion, or helper handling can fail before the intended assertion. Remove the auth argument and run both versions' anonymous and authenticated cases. This defect originates in public commit 3243fd7; preserve that history and add a follow-up fix. Runtime failure is not claimed: the test suite was not executed.
    2. R2 — Medium (P2): the stated integration order does not describe the actual topology. PR body “内容” item 2 and merge commit body line 4 claim the SPEC-01 public → private → adopted-PR order. However the first parent is the already-private tip 3f4c9cd, and the second is newer public tip bacfe64. SPEC-01 §4 rule 3 fixes the order. This is a private-seeded incremental public merge, not a literal execution of that recipe. The non-overlap makes the resulting content safe from a private/public conflict in this instance, but does not resolve the policy statement. Correct the PR explanation and record the owner's accepted bootstrap/incremental interpretation or exception in documentation; if strict reconstruction is required, propose it separately without rewriting or force-pushing upstream history. An additional commit can clarify the historical commit's assertion without amending it.
    3. R3 — Low (P3): a conversation-session URL is retained in metadata. PR body line 14 and merge commit body line 8 (Claude-Session) contain a link to an individual AI session. It is not a private repository URL, and no access token or password was found in the inspected PR metadata/delta. The session's contents and access controls were not inspected, so it is not proven to expose secrets. The owner should decide whether this provenance link belongs in durable metadata; remove it from the editable PR body if unnecessary. Do not reproduce the URL in public review records or rewrite history merely to remove a non-secret reference.

    Verification and evidence¶

    • Read gh pr view 1 -R RCOSDP/RDM-osf.io-dev2027 --json title,body,commits,files (also head/base SHA) and gh pr diff 1 -R RCOSDP/RDM-osf.io-dev2027.
    • gh api repos/RCOSDP/RDM-osf.io-dev2027/commits/546969eb33f42e35be5dc5c5ac8bfe55e3ef0bbc confirms exactly two parents: 3f4c9cd32e2e118f42a6b5aacbe2a5ff066a8a38 and bacfe64fdc002f09df47145fc17f57630772ac82. This is a real merge, not a squash. The three public commits retain their original SHAs: 5f78e37d591986ace4d241c992c1454e8af0a632 (permission), 3243fd7943428cb5e0c1f3a741b354dfa1369bdb (tests), and bacfe64fdc002f09df47145fc17f57630772ac82 (public PR merge). Historical force-push activity cannot be established from this snapshot alone.
    • The requested compare endpoint compare/upstream/public-develop...upstream/private-develop reports divergence: private ahead 161, behind 3, common ancestor b7eacc4c2f2a50f72f3489fc9c3d105b46ea8108. Its 260 changed files do not include either incoming file; thus there is no net file overlap, including private security changes. This checks net changes, not every transient edit in 161 commits.
    • Compared the pinned private tip → PR head against common ancestor → pinned public tip using the compare API. Both return exactly api/users/views.py and api_tests/users/views/test_user_detail.py; both patches and final blob SHAs match. No other private-base files change. This establishes preservation of the private tree, including hardening outside these files, rather than relying only on the PR's “no conflicts” claim.
    • api/users/views.py:177–184 requires authentication while retaining current-user/write and token-scope permissions. Inspected the test changes, api_tests/conftest.py:10–11, and tests/json_api_test_app.py:41–51 to identify the test application. Authenticated cross-user access remains tested in test_get.
    • The new integration commit uses a scoped Japanese merge(upstream): subject and includes reason, validation, and the explicit deferral of build/acceptance to M2. These requested convention elements are present; R2 concerns factual accuracy. Existing English upstream subjects should not be rewritten to enforce local style.
    • Manually inspected all four PR commit messages, PR body and two-file patch for secrets/credentials/private URLs. Found the session reference described in R3, no obvious credential and no private repository URL. This is not a full-history or automated secret scan.
    • GitHub checks at inspection: JavaScript/TypeScript CodeQL passed; Python CodeQL and two build-image jobs were pending. No local build, application test, or acceptance test was run. Pending checks are not passes, and static tree preservation is not proof of runtime compatibility.

    Owner decisions before merge¶

    Require R1's follow-up test correction and targeted execution evidence. Resolve R2's integration-order interpretation and accurately document it without rewriting upstream history. Decide R3's session-link retention and whether to accept deferring broader build/acceptance testing to M2; obtain the final required CI results. Explicitly accept that anonymous user-detail reads, including view-only-link requests, are now denied; validate dependent clients at M2. Preserve both upstream histories with a normal merge, not squash/rebase. This review makes no changes to the reviewed repository beyond the single requested PR comment.

    日本語¶

    判定: request changes（修正要求）¶

    対象は RCOSDP/RDM-osf.io-dev2027 PR #1、head 546969eb33f42e35be5dc5c5ac8bfe55e3ef0bbc。これはレビュー上の推奨判定であり、承認やマージ操作ではありません。2ファイルの差分から、本番コードの回帰や非公開側のセキュリティ変更の消失は見つかりませんでした。マージ前に R1・R2 を解決し、R3 は所有者が情報公開の観点から判断してください。

    重要度順の指摘¶

    1. R1 — 中（P2）: 未ログインの API 2.10 試験に認証引数が残っています。 head の api_tests/users/views/test_user_detail.py:260–262 は test_social_values_old_version_not_logged_in で auth=user_one を渡し、401 を期待しています。同じ試験の 2.9（256–258行）は認証なし、認証成功ケース（234–248行）は user_one.auth です。2.10 は資格情報が存在しない場合の純粋な試験になっておらず、渡した認証の拒否でも期待値を満たす、またはヘルパーの扱いによって検証前に失敗する可能性があります。auth 引数を除去し、両バージョンの未認証・認証済みケースを実行してください。公開コミット 3243fd7 由来なので、その履歴を保持して追加コミットで修正します。試験未実行のため、実行時の失敗を断定するものではありません。
    2. R2 — 中（P2）: 説明する統合順と実際の履歴が一致しません。 PR本文「内容」の2項目とマージコミット本文4行目は SPEC-01 の公開 → 非公開 → 採用PR の順を主張しています。しかし第1親は既に非公開側を含む 3f4c9cd、第2親が新しい公開側 bacfe64 です。SPEC-01 §4 規則3 の手順を文字どおり実施した形ではなく、非公開側起点の増分公開マージです。今回は差分ファイルが重ならず非公開・公開間の競合による消失はありませんが、規則との説明上の不一致は残ります。PR説明を訂正し、初期化・増分更新として認める解釈または例外を所有者判断として文書化してください。厳密な再構築が必要なら、上流履歴の書換えや force-push をせず別途提案します。過去コミットの説明は amend ではなく追加コミットで補足できます。
    3. R3 — 低（P3）: 会話セッションへのURLがメタデータにあります。 PR本文14行目、マージコミット本文8行目の Claude-Session に個別AIセッションへのリンクがあります。非公開リポジトリURLではなく、検査したメタデータ・差分にはアクセストークンやパスワードは見つかりませんでした。セッション内容とアクセス制御は確認していないため、秘密漏えいとは断定しません。所有者は永続メタデータに残す必要性を判断し、不要なら編集可能なPR本文から除去してください。公開レビュー記録にURLを転載せず、秘密でない参照を消すだけの目的で履歴を書き換えないでください。

    確認方法と根拠¶

    • 指定された gh pr view（title/body/commits/files、追加で head/base SHA）と gh pr diff を確認しました。
    • head のコミットAPIが返した親は 3f4c9cd32e2e118f42a6b5aacbe2a5ff066a8a38 と bacfe64fdc002f09df47145fc17f57630772ac82 の2つです。squash ではなく真のマージです。公開側の権限修正 5f78e37d591986ace4d241c992c1454e8af0a632、試験修正 3243fd7943428cb5e0c1f3a741b354dfa1369bdb、公開PRマージ bacfe64fdc002f09df47145fc17f57630772ac82 は元のSHAで保持されています。この時点の履歴だけから過去の force-push 有無までは判断できません。
    • 指定の compare/upstream/public-develop...upstream/private-develop は private ahead 161 / behind 3、共通祖先 b7eacc4c2f2a50f72f3489fc9c3d105b46ea8108 を返しました。非公開側の変更260ファイルと、今回の2ファイルとの積集合は空です。セキュリティ変更を含む最終差分の重複はありません。161コミット中の一時的な編集すべてを調べたという意味ではありません。
    • 固定した非公開tip→PR head と、共通祖先→固定した公開tip を compare API で比較しました。双方とも api/users/views.py と api_tests/users/views/test_user_detail.py の2ファイルだけで、patch と最終blob SHAも一致します。それ以外の非公開側ファイルは変更されておらず、関連するセキュリティ強化の保持を「衝突なし」という説明以外の根拠で確認しました。
    • api/users/views.py:177–184 で認証必須化と、本人による更新・トークンスコープ権限の保持を確認しました。試験差分、api_tests/conftest.py:10–11、tests/json_api_test_app.py:41–51 で試験アプリも確認しています。認証済み別ユーザーからの参照は test_get に残っています。

    • PRの4コミットのメッセージ、本文、2ファイルの差分を目視確認しました。R3 のセッション参照以外に明白な資格情報・非公開リポジトリURLはありません。全履歴の検査や自動秘密スキャンではありません。
    • 確認時点では JavaScript/TypeScript CodeQL が成功、Python CodeQL と2件の build-image は pending でした。ローカルのビルド・アプリ試験・受入試験は実行していません。pending は成功ではなく、静的なツリー保持だけでは動作互換性を保証しません。

    マージ前に所有者が決めること¶

    R1 の追加修正と対象試験の実行結果を求めてください。R2 の統合順の扱いを決め、上流履歴を書き換えず正確に記録してください。R3 のリンク保持と、広範なビルド・受入を M2 に延期することの受容可否を判断し、必須CIの最終結果を確認してください。view-onlyリンクを含め未認証のユーザー詳細参照が拒否される変更を明示的に受容し、依存クライアントは M2 で検証します。squash/rebase ではなく通常マージで両上流の履歴を保持してください。このレビューでは指定されたPRコメント1件以外、対象リポジトリを変更しません。
