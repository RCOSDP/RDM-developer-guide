## English

[→ 日本語版へ](#japanese)

### How to run

```sh
pip install -e "installer[accept]"
PLAYWRIGHT_BROWSERS_PATH=.venv/.playwright playwright install chromium
grdm-dev accept --seed                 # all scenarios, disposable users created and removed
grdm-dev accept --only C1              # one scenario (C1..C6, S1..S5, or a name fragment like login)
grdm-dev accept --only core --json     # every M2 scenario, report as JSON
```

`grdm-dev accept` is the only supported entry point: it checks that *Playwright* (a library that drives a browser for you) and *pytest* (the Python test runner) are importable, refuses any `--base-url` whose host is not `127.0.0.1`, and sets the environment the fixtures read. Running `pytest` by hand works for debugging only (`GRDM_BASE_URL=http://127.0.0.1:5000 pytest installer/acceptance -k c1`).

### Layout

```toon
files[6]{path,purpose}:
  conftest.py,"fixtures (base_url, ports, users, login, new_context, context_b, two_contexts, api_context, project, tmp_pdf/tmp_txt), time boxes, loopback guard, result collector"
  netguard.py,"is_loopback_origin / same_origin: exact (scheme, host, port) parsing; pure functions, unit-tested in installer/tests/test_accept.py"
  selectors.py,"every locator and URL path in one table; TODO(M2) marks entries not yet verified on the real app"
  test_c1_login.py … test_c6_admin.py,"core scenarios C1–C6; each has test_*_success and test_*_rejection; marker core"
  test_s1_y_websocket.py … test_s5_shibboleth.py,"subsystem stubs S1–S5; marker subsystem; skipped with reason M3"
  pytest.ini,"markers and default options"
```

Every test carries `scenario(id, name)` and `case("success" | "rejection")` markers; the collector hook copies them into `results.json`, together with `http_status` when a test calls `record_property("http_status", n)`.

### Rules the fixtures enforce

- **Loopback (the network path back to your own computer) only.** Every browser context (and every page in it) is routed so that a request whose origin is not exactly `http://127.0.0.1:<port>` is aborted; WebSockets are routed the same way (`ws://127.0.0.1:<port>` only), service workers are blocked (`service_workers="block"`), and API calls go through `api(context)` / `api_context()`, which check the URL before sending, do not follow redirects unless the test passes `max_redirects`, and check the answered URL. Any offending URL fails the test ([SPEC-04 §3.4](../../docs/spec/04_acceptance_tests.md), [ADR-02](../../docs/decisions/ADR-02_Network_Model.md)). Tests never call `playwright.request.new_context()`, `browser.new_context()` or `<context>.request` directly; a unit test enforces this.
- **Time boxes.** 120 s per test (`SIGALRM`), 30 minutes per suite.
- **Disposable data.** Users come from `grdm-dev accept --seed` as `user-a-<run_id>@acceptance.test` and similar; with *fakecas* (the fake login server of the development stack) the password is the e-mail address. Projects created by the `project` fixture are deleted in teardown. Test files are generated bytes.
- **No host state.** Only `runtime/.env` (`GRDM_PORT_<SERVICE>`) and the `GRDM_*` variables set by `grdm-dev accept` are read.

### Evidence

`grdm-dev accept` first runs the integration precheck (`grdm_dev.health.check_services`: every service running and every HTTP probe answering; exit 40 otherwise, before any browser starts), then writes `docs/demo/runs/<run_id>/` with `results.json` (canonical), `results.toon`, `junit.xml`, `pytest.log`, `collector.json` (raw per-test records), and `artifacts/<test>/` holding screenshots only for failed tests. Browser traces are off by default; with `--trace` they are kept only on failure and moved to `runtime/reports/quarantine/<run_id>/` (private, git-ignored) because a trace can contain cookies and response bodies. Every value of `runtime/.env` (except ports and profile) and every token-like string is masked as `***` in all text files and in anything printed; the run directory is `0700` and its files `0600`. A run with no result rows, or in which a selected scenario lacks a success or a rejection row, exits 60 even if pytest was green. Each row of `results.json` has `id`, `name`, `case`, `test`, `status`, `duration_ms`, `http_status`, `evidence`. See [docs/demo/runs/README.md](../../docs/demo/runs/README.md).

### Not yet verified (M2)

Selectors and URL paths marked `TODO(M2)` in `selectors.py`, the seed management command in `grdm_dev/accept.py`, the CSRF header for session-cookie writes to the API, the waterbutler (the file-transfer service) cookie forwarding, the websocket URL exposed by the wiki page, and the institution id used by C6.

### 実行方法

```sh
pip install -e "installer[accept]"
PLAYWRIGHT_BROWSERS_PATH=.venv/.playwright playwright install chromium
grdm-dev accept --seed                 # 全シナリオ。使い捨て利用者を作って消す
grdm-dev accept --only C1              # 一つだけ（C1〜C6、S1〜S5、または login のような名前の一部）
grdm-dev accept --only core --json     # M2 の全シナリオ。報告を JSON で
```

正式な入口は `grdm-dev accept` だけです。*Playwright*（ブラウザを代わりに操作してくれるライブラリ）と *pytest*（Python の試験を動かす道具）が読み込めることを確かめ、ホストが `127.0.0.1` でない `--base-url` を拒み、フィクスチャが読む環境変数を設定します。`pytest` を直接動かすのはデバッグ用です（`GRDM_BASE_URL=http://127.0.0.1:5000 pytest installer/acceptance -k c1`）。

### 構成

```toon
files[6]{path,purpose}:
  conftest.py,"フィクスチャ（base_url・ports・利用者・login・new_context・context_b・two_contexts・api_context・project・tmp_pdf/tmp_txt）、時間制限、ループバック監視、結果収集"
  netguard.py,"is_loopback_origin / same_origin。(scheme, host, port) を厳密に解析する純関数。installer/tests/test_accept.py で単体試験"
  selectors.py,"ロケータと URL パスを一つの表に。実機で未確認のものは TODO(M2)"
  test_c1_login.py … test_c6_admin.py,"コアシナリオ C1〜C6。test_*_success と test_*_rejection。マーカー core"
  test_s1_y_websocket.py … test_s5_shibboleth.py,"サブシステムの骨格 S1〜S5。マーカー subsystem。理由 M3 でスキップ"
  pytest.ini,"マーカーと既定オプション"
```

各試験は `scenario(id, name)` と `case("success" | "rejection")` のマーカーを持ち、収集フックがそれを `results.json` に写します。試験が `record_property("http_status", n)` を呼ぶと `http_status` も記録されます。

### フィクスチャが守らせる規則

- **ループバック（自分の計算機へ戻るネットワークの道）だけ。** すべてのブラウザ文脈（とその中の全ページ）に経路を仕込み、起点が厳密に `http://127.0.0.1:<port>` でない要求は中断します。WebSocket も同様に経路を通し（`ws://127.0.0.1:<port>` だけ）、サービスワーカーは遮断し（`service_workers="block"`）、API 呼び出しは `api(context)` / `api_context()` を通します。これらは送る前に URL を確かめ、試験が `max_redirects` を渡さない限り転送に従わず、応答の URL も確かめます。違反する URL が一つでもあれば試験は失敗です（[SPEC-04 §3.4](../../docs/spec/04_acceptance_tests.md)、[ADR-02](../../docs/decisions/ADR-02_Network_Model.md)）。試験は `playwright.request.new_context()`・`browser.new_context()`・`<context>.request` を直接呼びません。単体試験がこれを検査します。
- **時間制限。** 試験ごとに 120 秒（`SIGALRM`）、スイート全体で 30 分。
- **使い捨てデータ。** 利用者は `grdm-dev accept --seed` が `user-a-<run_id>@acceptance.test` のように作ります。*fakecas*（開発環境の偽のログインサーバ）ではパスワードはメールアドレスです。`project` フィクスチャが作ったプロジェクトは後片付けで消します。試験ファイルは生成したバイト列です。
- **ホストの状態を読まない。** 読むのは `runtime/.env`（`GRDM_PORT_<SERVICE>`）と `grdm-dev accept` が設定する `GRDM_*` 変数だけです。

### 証跡

`grdm-dev accept` はまず統合の事前確認（`grdm_dev.health.check_services`。全サービスが稼働し、全 HTTP 探査が応えること。満たさなければブラウザを起動する前に終了 40）を行い、次に `docs/demo/runs/<run_id>/` に `junit.xml`、`results.json`／`results.toon`、`pytest.log`、`collector.json`（試験ごとの生の記録）を書き、失敗した試験についてだけ `artifacts/<試験>/` にスクリーンショットを置く。ブラウザのトレースは既定では記録しない。`--trace` のときだけ失敗時に残し、cookie や応答本文を含み得るため `runtime/reports/quarantine/<run_id>/`（非公開、git 管理外）へ移す。`runtime/.env` の値（ポートとプロファイルを除く）とトークンらしい文字列は、すべてのテキストファイルと表示で `***` に置き換えます。実行フォルダは `0700`、ファイルは `0600` です。結果の行が一つもない実行や、選んだシナリオに成功・拒否のどちらかの行が欠ける実行は、pytest が緑でも終了 60 です。`results.json` の各行は `id`・`name`・`case`・`test`・`status`・`duration_ms`・`http_status`・`evidence` を持ちます。[docs/demo/runs/README.md](../../docs/demo/runs/README.md) を参照。

### 未確認事項（M2）

`selectors.py` の `TODO(M2)` 付きのロケータと URL パス、`grdm_dev/accept.py` の seed 管理コマンド、セッション cookie で API に書き込むときの CSRF ヘッダ、waterbutler（ファイルを出し入れする部品）への cookie 転送、Wiki 画面が公開する websocket の URL、C6 で使う機関 ID。

## Glossary / 用語

| Term | English note | 日本語注 |
|---|---|---|
| Fixture | Ready-made data or setup a test receives before it starts. | 試験が始まる前に受け取る、用意済みのデータや準備。 |
| Browser context | A separate browser session with its own cookies, inside one test. | 一つの試験の中にある、cookie を別々に持つ独立したブラウザのセッション。 |
| Marker | A label on a test that lets the runner select or describe it. | 試験に付ける札。実行する試験の選択や説明に使う。 |
| Loopback | The network path back to your own computer; `127.0.0.1`. | 自分のコンピュータに戻る通信路。`127.0.0.1`。 |
| Seed | Creating the throw-away users a test run needs. | 試験の実行に必要な使い捨ての利用者を作ること。 |
