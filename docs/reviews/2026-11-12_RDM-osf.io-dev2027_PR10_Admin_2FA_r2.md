### R2-01 — P1 — Integrate the global guard before declaring the admin boundary complete

**Location:** `admin/common_auth/middleware.py:20–25`, `admin/base/settings/defaults.py:223–245`, `admin/README.md:66–67`; affected view: `admin/institutions/views.py:235–241`.

The 2FA middleware logs out an unverified, expired-grace or disabled session, then calls the next handler. At the reviewed head, `AdminLoginRequiredMiddleware` does not exist in `admin/base/middleware.py` and is absent from `MIDDLEWARE`. `CannotDeleteInstitution` has no own authentication check. Thus `/institutions/<id>/cannot_delete/` can still execute after the logout, and a verified user who loses staff rights is not rejected by this middleware. The README claims that the global guard already runs after 2FA, which is not true of this branch. The PR body's r1 response table similarly says develop was merged, although its later integration-status section correctly says #8 is still open and describes a temporary tree.

**Reproduction:** an extracted real `TwoFactorSessionMiddleware` and `CannotDeleteInstitution`, running on Django 1.11.28, invoked the institution lookup and returned a status-200 TemplateResponse for anonymous, pending-only, unverified, expired-grace, disabled and nonstaff requests. The lookup was mocked and the template was not rendered; this proves view execution, not an end-to-end browser response. Composing the same chain with #8's real `process_view` rejected anonymous/pending/unverified/expired-grace/disabled requests before the lookup (302), allowed a verified active staff user (200), and rejected a verified nonstaff user (`PermissionDenied`, converted to 403 by Django). The URL reversal was stubbed. Both probes passed their assertions, including reproduction of the defect.

This is the pre-existing global protection gap recorded as R1-02, not a claim that the r2 change introduced a new endpoint. The grace-marker validation itself is fixed; preventing the logged-out request from reaching every private view still depends on #8. Approval remains blocked until the dependency is present and tested in the actual #10 head.
