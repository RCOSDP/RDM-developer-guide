### R6-05 — closed: child counts follow the private-mode list

`NodeSerializer.get_node_count`, at `api/nodes/serializers.py:666–674`, selects `Node` or `Registration` from the parent type, starts with `default_node_list_queryset`, restricts membership to direct non-link children, applies `.can_view(auth.user, auth.private_link)`, then counts. The corresponding unfiltered children list uses the same model, default queryset, child-membership filter and visibility method at `api/base/views.py:491–503`. List ordering and request filters are presentation concerns; the relationship count is the total unfiltered authorized set, not the length of a filtered or paginated response.

The default queryset excludes deleted records. In private mode, `AbstractNodeQuerySet.can_view` does not add stored-public children and does not honor the private-link shortcut. It retains explicit READ, OSF group access and inherited ordinary parent ADMIN through the existing visibility helper. Membership subqueries select nodes rather than permission rows or relation rows, avoiding duplicate counts from overlapping grants. The storage annotation traverses a one-to-one node-settings relation (`addons/base/models.py:360`) and a single region foreign key, so it does not multiply node rows. Inspection of the pinned django-guardian v1.5.1 source also confirms that the single-READ permission path filters by primary-key membership rather than joining permission rows into the returned nodes. The source probe also checks node and registration model selection, deleted children, links, grandchildren and duplicate relations. The Mapcore limitation is separated under [follow-up](#followup-en).

Public mode bypasses the new branch and executes the old SQL with the same parameters. An independent AST comparison (comparison of parsed Python structure) removes only the new private branch and finds the entire remaining method identical to `71e26d2751`. This preserves the existing public-mode behavior, including the existing view-only-link count/list asymmetry; this review does not claim to fix that public-mode asymmetry. The new imports do not change the default-query helper itself.

The regression file constructs legacy public records while public access is enabled, switches the setting, then sends real WebTest requests to both the parent detail with `related_counts=children` and `/children/`. It asserts expected IDs as well as count/list agreement for a parent reader with child READ, an OSF group member, parent ADMIN and a view-only link. Four inherited public-mode methods bring the addition to eight collected tests, but the public-mode view-only method returns without assertions: there are seven substantive new cases, not eight independent boundary checks. No new real-request registration or Mapcore case was added. The AID's audit correction from 15 to 17 fixed public-flag/link occurrences correctly reclassifies the two old SQL alternatives as authorization decisions rather than display values.

### Query cost and independent validation

The new serializer branch performs one canonical visibility calculation and one database count. It does not load every child into Python or make one authorization query per child. However, `.can_view()` is not one SQL query: `_visible_to_user` materializes the user's direct node IDs, loads admin roots, then queries descendants once per hierarchy level. It traverses the user's visible/administered graph, not only the requested parent's children. Repeated relationship counts across many parent objects repeat that work.

This is the same visibility cost already used by one children-list evaluation, plus counting instead of fetching rows. It is a reasonable correctness fix for this scope, with no new query in public mode. There is no measured production-scale latency claim. Large hierarchies and bulk `related_counts=children` requests merit a later performance check; optimizing or caching must preserve current permission revocation and list/count agreement.

REV ran extracted real count, list, default-query and visibility methods against a minimal Django 2.2.28/SQLite schema. Ten cases pass across nodes and registrations: reader, overlapping group grants, parent ADMIN, outsider and reader with a private link. The fixture additionally includes deleted children, a linked node, a grandchild and a duplicate relation. The expected counts are 1, 1, 4, 0 and 1 for each model type. The simplified probe observes five count-path queries for non-admin cases and eight for the fixture's admin hierarchy. Those are probe measurements, not production query budgets: guardian's permission-selection collaborator is simulated, and the application HTTP stack, full schema and PostgreSQL are not executed.

Both modified Python files compile in memory, and `git diff --check` passes. The public-mode AST comparison passes. Evidence files are `source-probe.py`, `source-probe.json`, `mapcore-probe.py`, `mapcore-probe.json`, `coverage-inventory.json` and the inspected upstream `guardian-shortcuts-1.5.1.py`, retained in reviewer scratch storage without public filesystem links. ### Follow-up: existing Mapcore under-visibility

The r6 request also mentioned preserving Mapcore access. The canonical children list already calls `.can_view(user, private_link)` with `include_mapcore_groups=False`, and `_visible_to_user` calls `get_nodes_for_user` with that default too. Separate Mapcore memberships are not ordinary OSF/Django group memberships. The new count inherits that existing list limitation.

An isolated source probe gives a user ordinary READ on the parent plus ADMIN only through an active Mapcore membership. With one private direct child, the previous raw SQL count is 1, the new count is 0 and the unchanged list is empty. Thus count/list consistency is verified, but full Mapcore compatibility is not. This is an under-visibility/feature limitation, not the over-disclosure that R6-05 reported. The coordinator explicitly directed closing R6-05 for the disclosure fix and recording Mapcore as a follow-up outside #8's pre-merge corrections.

A future change should align Mapcore-authorized child lists and counts, with active/revoked group, READ/ADMIN and descendant tests, without restoring public-flag or view-only-link bypasses. The earlier broad Mapcore-preservation expectation must not be presented as a passed test in r7.
