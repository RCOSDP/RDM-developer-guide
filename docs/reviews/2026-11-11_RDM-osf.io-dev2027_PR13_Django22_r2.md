### Verdict and closure

**Pass for this round's R1/R2 scope. No new blocking regression found.** This verdict is a review comment, not a GitHub approval or permission to merge. The requested r1 file was absent, so the r1 comment `6763600948` was read from the PR conversation.

R1 is closed. ODMBackend (REV scratch evidence (not published): `api/base/authentication/backends.py`) now accepts `(request=None, username=None, password=None, **kwargs)` and rejects missing credentials before calling the existing identity lookup. LoginView (REV scratch evidence (not published): `admin/common_auth/views.py`) passes the actual request. The guardian adapter accepts the same signature and always returns `None`, retaining its parent's object-permission implementation. Existing ODM session backend identifiers remain unchanged. Guardian was not a successful login backend, so changing its configured dotted path does not invalidate a legitimate guardian-authenticated session.

R2 is closed. Django defaults (REV scratch evidence (not published): `api/base/settings/defaults.py`) explicitly set session and CSRF SameSite to `Lax`; admin inherits them. Both settings loaders validate after their own local overrides. The Flask `osf` cookie policy is unchanged. Django 2.2.28's actual session middleware successfully creates, refreshes and deletes a Lax cookie in the isolated probe; the old string `'None'` raises `ValueError`. Python `None` omits the attribute. The guard deliberately permits only canonical `None`, `Lax`, and `Strict`, which is stricter than Django's handling of lowercase strings and empty values.
