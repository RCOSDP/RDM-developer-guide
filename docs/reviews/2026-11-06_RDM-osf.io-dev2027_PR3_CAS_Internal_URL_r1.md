### Verdict and scope

**PASS with non-blocking test suggestions.** This is a source review, not a GitHub approval or authorization to merge. CAS (the shared login service) keeps its browser address while server requests can use a Compose service name, matching ADR-02 without a loopback alias. The local branch reference matches the reviewed head. GitHub reports exactly three changed files: `framework/auth/cas.py`, `website/settings/defaults.py`, and `tests/test_cas_client_internal_url.py`; the complete diff contains no unrelated changes.

### Call-site audit

| Path | Evidence and result |
|---|---|
| Ticket validation | `framework/auth/cas.py:118–125` sends GET to `INTERNAL_URL/p3/serviceValidate`; the service parameter remains the caller's external URL. `make_response_from_ticket` uses `get_client()`. |
| OAuth profile | `cas.py:99–102,139–143` uses `INTERNAL_URL/oauth2/profile`. `framework/auth/core.py:89` and `api/base/authentication/drf.py:283` obtain that client. |
| Token revocation | `cas.py:104–107,188–192` sends POST to `INTERNAL_URL/oauth2/revoke`. Application/token API deletion flows through `osf/models/oauth.py:73–75,88–89,143–147` and the same client. |
| Browser login/logout | `cas.py:81,94` retains `BASE_URL`; wrappers and nested logout/login chains retain it. Authentication views, profile views, project decorators and contributor views all use these helpers. Institution campaigns at `framework/auth/views.py:252,397` are unchanged. |
| Literal external addresses | `website/routes.py:179,183`, `website/profile/utils.py:64,74`, and `api/institutions/authentication.py:252` construct browser-facing login/MFA destinations. `framework/auth/views.py:1127` validates browser return destinations. Keeping `CAS_SERVER_URL` is correct. |
| Template context | `website/routes.py:184` now supplies an internal profile URL to context. Searches of templates and JavaScript found no consumer of that CAS context value; other profile URLs are user/add-on links. No active browser request or redirect regression was found, but future consumers must not use this internal value in the browser. |
| Admin | Search found no separate CAS HTTP request or redirect implementation in `admin`; no missed direct server call was found across the four requested trees. |

### Compatibility and tests

`get_client()` uses `getattr(settings, 'CAS_INTERNAL_SERVER_URL', None)`, and the constructor falls back with `internal_base_url or base_url`. An absent setting, explicit `None`, or an empty string preserves the old address; existing one-argument constructors still work. Defaults add only `CAS_INTERNAL_SERVER_URL = None`.

The new `tests/test_*.py` file, `Test*` class, `test_*` methods and `monkeypatch` fixture fit pytest 5.0.0 and the repository's `pytest.ini`; there is no test-path restriction excluding it. The nested fake response and byte-string XML are valid Python 3.6 syntax by inspection. The authentication-failure XML returns an unauthenticated response without raising, so the new validation test is structurally sound. Root `conftest.py` still loads application dependencies and automatic fixtures: this is not an independently runnable dependency-free test.

**N1 — non-blocking:** `tests/test_cas_client_internal_url.py:13` replaces text in the profile URL and therefore does not test fallback ticket validation. Replace it with a direct profile assertion and mock the actual default-address `service_validate` request; also assert that the external service query parameter is unchanged.

**N2 — non-blocking:** all three tests construct `CasClient` directly. Add `get_client()` cases for a configured internal setting and an absent setting to protect the configuration wiring. The implementation is correct by inspection, but removing that wiring would leave these tests green.

### Validation limits

Compilation of all three changed Python files succeeded with local Python 3.15.2; existing invalid-escape warnings in defaults at lines 2119–2121 are outside this diff. This does not prove execution under Python 3.6. No pytest suite, live CAS/browser scenario, or Docker operation was run. GitHub checks were pending when inspected. Runtime login, profile, revocation and redirect-chain acceptance checks remain for the integration environment; no code changes are requested as a blocking condition.

### 判定と範囲

**PASS（テスト補強の非阻害提案あり）。** ソースのレビューであり、GitHub の承認やマージ許可ではない。CAS（共通のログインサービス）のブラウザ用アドレスを保ち、サーバー通信だけ Compose のサービス名に切り替える実装は、ループバック別名を使わない ADR-02 と整合する。ローカルのブランチ参照は対象 head と一致した。GitHub の変更ファイルは `framework/auth/cas.py`、`website/settings/defaults.py`、`tests/test_cas_client_internal_url.py` の三つだけで、全差分に無関係な変更はなかった。

### 互換性とテスト

`get_client()` は `getattr(settings, 'CAS_INTERNAL_SERVER_URL', None)` を使い、コンストラクターは `internal_base_url or base_url` で元のアドレスに戻る。設定の欠落、明示的な `None`、空文字列では従来のアドレスを保つ。既存の引数一つの呼び出しも動く。既定値の追加は `CAS_INTERNAL_SERVER_URL = None` だけ。

追加ファイルの `tests/test_*.py`、`Test*` クラス、`test_*` メソッド、`monkeypatch` は pytest 5.0.0 と既存 `pytest.ini` の規約に合い、収集対象から除外する設定もない。内部クラスの偽応答とバイト列 XML は目視上 Python 3.6 で有効な構文。認証失敗 XML は例外ではなく未認証の応答になるため、新しい検証テストの構造は正しい。ルートの `conftest.py` はアプリの依存関係と自動 fixture を読み込むため、依存なしで単独実行できるテストではない。

**N1 — 非阻害:** `tests/test_cas_client_internal_url.py:13` は profile URL の文字を置換しており、既定アドレスでのチケット検証を試していない。profile の直接比較と、既定アドレスへの実際の `service_validate` を模擬する検証に置き換え、外部 service クエリー引数が保たれることも確認するとよい。

**N2 — 非阻害:** 三つのテストはすべて `CasClient` を直接作る。内部設定あり・設定欠落の `get_client()` テストを足して、設定の受け渡しを保護するとよい。実装は目視上正しいが、この受け渡しを消しても現状のテストは通る。

### 検証の限界

変更した Python 三ファイルはローカル Python 3.15.2 の構文コンパイルに成功した。defaults の 2119–2121 行に既存のエスケープ警告が出たが差分外。これは Python 3.6 での実行証明ではない。pytest スイート、実際の CAS・ブラウザ操作、Docker 操作は実行していない。確認時の GitHub 検査は実行待ち・実行中だった。ログイン・profile・失効・転送連鎖の受入試験は統合環境に残るが、阻害条件として求めるコード修正はない。
