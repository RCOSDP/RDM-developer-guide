### Verdict and scope

**PASS.** No blocking security, correctness, or documentation finding in the nine changed files. Reviewed a clean detached clone, the full PR diff, rendered configuration tests, and a separate clean clone of RDM-osf.io-dev2027 at `8fc45de461fde227dc60c30a47139a61d6209a26`.

### Evidence

1. `installer/grdm_dev/compose.py:881–883` writes `mongodb://mongo:27017/sharejs?ssl=true` and `/mongo-tls/mongodb.crt`. The URL contains no credentials or verification bypass. Its hostname matches `CN=mongo` and `subjectAltName=DNS:mongo` in `templates/mongo.json`; its database and TLS option match `render_sharejs_env()`.
2. The four added mounts are `mongo_tls:/mongo-tls:ro` in web, api, admin and worker. The only other consumers are the existing mongo writer and sharejs read-only client. The private PEM stays in `mongo_data`, which none of those four services mount; only the public certificate is copied, with mode 0644.
3. The new renderer test checks both environment entries, all four read-only mounts, absence of `mongo_data`, and the certificate export and SAN. Existing tests check the sharejs recipe and the resolved websocket secret equality.
4. The old pin `fe90e5c39e660f464bb8fcc9ae4028119b958d19` to new pin diff contains only PR #9: wiki defaults, TLS utility code, and TLS tests. The fetched osf.io `develop` equals the new pin. `addons/wiki/settings/defaults.py:26` reads `SHAREJS_DB_CA_FILE`; `share_db_client_options()` supplies `ssl_ca_certs`, and `share_db()` rejects weakening URL options. No Dockerfile or other settings migration is introduced by the pin.
5. osf.io PR #8 was **OPEN**, with no merge commit or merge date at review time. `ENABLE_PUBLIC_ACCESS` is absent from the pinned website/API/admin code, so that unmerged setting requires no installer change in PR #43. Reassess it when PR #8 is integrated.
6. `Y_WEBSOCKET_SECRET` is read by wiki defaults and used by the Flask wiki page/token routes. Existing `web.json:29` maps it to `${Y_WEBSOCKET_JWT_SECRET}`, matching y-websocket's `JWT_SECRET`. Other services retain the older alias but do not serve those token routes; this pin introduces no new consumer needing the mapping.
7. ADR-07 now describes certificate and hostname verification in both languages, consistently with the pinned client; the stale CERT_NONE description is removed.

### Validation and limits

The final commands use the available system `python3` and the documented import path.

No live TLS handshake or fresh-stack acceptance was performed. Tests use temporary synthetic configuration; no deployed `runtime/.env` was accessed, and no Docker stack state was changed. Existing certificates are not regenerated by the template: installation acceptance must still verify the persisted certificate and first-start availability. No commit, push, approval, merge, or closure was performed.

### 判定と範囲

**PASS（合格）。** 変更された 9 ファイルに、統合を妨げるセキュリティ・動作・文書の指摘はない。クリーンな detached clone で差分全体と描画テストを確認し、別のクリーンな clone で RDM-osf.io-dev2027 の固定版 `8fc45de461fde227dc60c30a47139a61d6209a26` を照合した。

### 根拠

1. `installer/grdm_dev/compose.py:881–883` の URL は `mongodb://mongo:27017/sharejs?ssl=true`、CA は `/mongo-tls/mongodb.crt`。資格情報も検証回避オプションもなく、ホスト名は mongo の証明書生成条件 `CN=mongo` / `subjectAltName=DNS:mongo` と一致する。DB 名と TLS オプションも sharejs の描画設定と一致する。
2. 追加マウントは web・api・admin・worker の `mongo_tls:/mongo-tls:ro` のみ。他は既存の mongo 書き込み元と sharejs 読み取り専用クライアントだけ。秘密 PEM は `mongo_data` に残り、4 サービスには渡らない。公開証明書だけがモード 0644 でコピーされる。
3. 新しい描画テストは環境変数 2 件、4 サービスの読み取り専用マウント、`mongo_data` 非共有、証明書の出力先と SAN を確認する。既存テストは sharejs 設定と websocket 秘密値の一致を確認する。
4. 旧固定 `fe90e5c39e660f464bb8fcc9ae4028119b958d19` からの差分は PR #9 の wiki 設定・TLS 実装・TLS テストだけ。取得した osf.io develop は新固定と一致する。wiki defaults が CA 環境変数を読み、`share_db_client_options()` が `ssl_ca_certs` を渡し、`share_db()` が検証回避 URL を拒む。Dockerfile や他の設定移行は含まれない。
5. osf.io PR #8 は確認時点で **OPEN**、マージコミット・日時とも未設定。固定版の website/API/admin に `ENABLE_PUBLIC_ACCESS` はないため、本 PR での追加設定は不要。PR #8 統合時には再確認が必要。
6. `Y_WEBSOCKET_SECRET` を読むのは wiki defaults で、Flask の wiki ページ・トークン発行経路が使用する。既存 `web.json:29` は `${Y_WEBSOCKET_JWT_SECRET}` を渡し、y-websocket の `JWT_SECRET` と一致する。他サービスは旧名を保持するが、このトークン経路を提供せず、今回の固定変更で新たな利用箇所も増えていない。
7. ADR-07 は英和とも証明書・ホスト名の検証を説明し、固定版の実装と一致する。古い CERT_NONE の説明は除去されている。

クリーンな guide clone で仮想環境を使わず、システムにある `python3`（`/opt/homebrew/bin/python3`、Python 3.15.2）で英語節の 4 コマンドを実行した。

実接続や新規スタックの受入は未実施。テストは一時領域の合成設定を使い、稼働環境の `runtime/.env` にはアクセスせず、Docker スタックの状態も変更していない。既存証明書はテンプレートで再生成されないため、配備時に永続化された証明書と初回起動時の可用性を確認する必要が残る。commit・push・approve・merge・close は行っていない。
