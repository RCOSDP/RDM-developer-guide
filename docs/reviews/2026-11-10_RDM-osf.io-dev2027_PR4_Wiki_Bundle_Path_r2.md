### Verdict and R1 disposition

**Pass for PR #4 r2; no blocking new finding.** [Previous R1-01](2026-11-07_RDM-osf.io-dev2027_PR4_Wiki_Bundle_Path_r1.md#english) is resolved at the source/deployment-contract level by `addons/wiki/bundle.py:49–82`, `tasks/__init__.py:846–851` and `README-docker-compose.md:397–410`. Non-development deployments now have an explicit instruction to build the frontend overlay, extract the output and run `invoke wiki_bundle --source <output directory>`. The helper copies all output pieces and creates the stable alias. This is a manual prerequisite, not automatic integration into the ordinary osf.io Dockerfile. No claim is made that production already runs it or that browser acceptance passed. The chain still requires the frontend token-renewal fix.

### Selection, path and XSS checks

`editor_script_url` checks the configured `STATIC_FOLDER/public/js/wiki/wiki-edit-page.js` and returns one of two fixed literal URLs. No user input, filename or source argument is interpolated into the script attribute. The attribute is now quoted (`edit.mako:737`), and no new HTML/script injection path was found. The module-level Mako import compiles successfully. Both URLs assume the existing `/static` prefix; default settings match it. A remote static store must mirror the alias locally for this existence check or adapt the selection contract; external-only asset publication was not verified.

The alias absent case logs once per process and selects the legacy path. That raw source still contains CommonJS imports and is not a working fallback on a clean checkout. The README explicitly describes this limitation and says the legacy path works only where deployment replaces it with built output. Thus installing the overlay remains necessary; the new conditional alone does not fix a clean non-dev build.

`install_bundle` requires exactly one hexadecimal-hashed entry and copies chunks, subdirectories and other output before updating the alias. It writes below the configured static wiki directory; it does not interpret the source path as a browser URL. Input is a trusted operator-supplied build directory, not an HTTP parameter. It is not a sandbox against malicious symlinks or an untrusted build tree. Use a separate extracted build directory, not the destination or a parent containing the destination.

### R2-01 [P3, advisory]: make live replacement atomic or document an offline install

`addons/wiki/bundle.py:64–81` copies files in place, copies the alias with `shutil.copy2`, and immediately prunes older chunks. The comment that the directory is never empty is narrower than an uninterrupted deployment guarantee: a concurrent request may read the alias while it is being replaced, and an already-open page may request an old chunk after pruning. For live production updates, stage and atomically publish the alias/versioned directory and retain older assets for active clients; alternatively state that the helper runs before serving requests. This does not block the documented pre-serving installation use case. A live-concurrency test was not performed.

### Tests, chain and limits

Nine `addons.wiki.tests.test_bundle` unittest cases passed in a scratch virtual environment, including actual Mako compilation, fallback, alias/chunk copying, replacement/pruning and invalid source selection. No full app settings import or Invoke task execution was tested; the task is a thin registered wrapper around the tested installer. Read the pinned Invoke 0.15.0 requirement and task registration. No production frontend build, real generated-chunk HTTP fetch, browser C4 or CDN configuration was exercised.

The unchanged issuer uses HS256, UUID document scope, string user subject and eight-hour expiry, and serializes the page token with `sjson`. Its extracted real mint function with PyJWT 1.5.3 produced a token accepted by server PR #2. This PR does not add renewal; frontend PR #3 must handle expiry/reconnect. The omitted frontend Docker auth wrapper is superseded by server PR #2, not by this template change.

Only scratch clones, host-only tests, three review files and one comment per PR were used. No grdm-dev Docker state or runtime/.env was accessed or modified; no application commit, push, merge or approval was made.

### 判定と R1 の扱い

**PR #4 r2 は pass。新たな必須修正なし。** [前回 R1-01](2026-11-07_RDM-osf.io-dev2027_PR4_Wiki_Bundle_Path_r1.md#japanese) は `addons/wiki/bundle.py:49–82`、`tasks/__init__.py:846–851`、`README-docker-compose.md:397–410` により、ソースと配備の前提の面では解決。非開発環境では frontend overlay を build し、出力を取り出して `invoke wiki_bundle --source <出力ディレクトリ>` を実行する指示が追加された。全出力のコピーと固定名の作成を行う。これは手動の前提手順であり、通常の osf.io Dockerfile への自動統合ではない。本番で実行済み、ブラウザ受入済みという意味ではない。経路全体には frontend のトークン更新修正が残る。

### 選択・パス・XSS の確認

`editor_script_url` は設定された `STATIC_FOLDER/public/js/wiki/wiki-edit-page.js` を確認し、2つの固定 URL の片方を返す。利用者入力、ファイル名、source 引数を script 属性に入れない。属性は引用符付きになり（`edit.mako:737`）、新たな HTML/script 注入経路は見つからなかった。Mako のモジュール import は実際に compile できた。両 URL は既存の `/static` 前提で、既定設定に一致する。外部の静的配信先だけへ配置する構成では、存在確認用の alias をローカルにも置くか選択の前提を変更する必要がある。外部配信のみの構成は未検証。

alias が無ければプロセスごとに一度警告し旧パスを選ぶ。その生ソースは引き続き CommonJS import を含み、クリーン checkout では動く代替にならない。README は制約を明記し、旧パスが動くのはその場所を build 済み出力に置換した配備だけと説明する。overlay の配置は依然必要で、条件分岐だけでクリーンな非開発 build が直るわけではない。

`install_bundle` は16進ハッシュ付き entry がちょうど1つであることを要求し、chunk・下位ディレクトリ・他の出力をコピーして alias を更新する。書込先は設定された静的 wiki ディレクトリ配下で、source をブラウザ URL として解釈しない。入力は運用担当者が渡す信頼済み build ディレクトリで、HTTP 引数ではない。悪意ある symlink や不正 build tree を隔離する機構ではない。出力先自身や出力先を含む親ではなく、別に取り出した build ディレクトリを使うこと。

### R2-01［P3、助言］：稼働中の置換を不可分にするか停止中の配置と明記する

`addons/wiki/bundle.py:64–81` はその場でコピーし、`shutil.copy2` で alias を更新して旧 chunk をすぐ削除する。「ディレクトリが空にならない」というコメントは、無停止配備の保証ではない。同時リクエストが置換中の alias を読む可能性や、開いているページが削除済みの旧 chunk を要求する可能性がある。本番稼働中の更新には、別の場所で準備して alias/版ディレクトリを不可分に切り替え、稼働中の利用者向けに旧出力を保持するか、リクエスト公開前に実行する手順と明記すること。文書の公開前配置という用途を妨げる必須修正ではない。稼働中の並行試験は実施していない。

### 試験・関連経路・限界

scratch の仮想環境で `addons.wiki.tests.test_bundle` の unittest 9件に合格。実 Mako compile、fallback、alias/chunk コピー、置換/削除、不正 source 選択を含む。アプリ全体の settings import や Invoke task の実行は未検証。task は試験済み installer を呼ぶ薄い登録関数である。固定された Invoke 0.15.0 と task 登録を読んだ。本番用 frontend build、実生成 chunk の HTTP 取得、ブラウザ C4、CDN 設定は未検証。

変更されていない発行側は HS256、UUID 文書範囲、文字列の利用者、8時間の期限を使い、`sjson` でページに出力する。PyJWT 1.5.3 による実発行関数の抽出実行結果は server PR #2 に受理された。この PR は更新機能を追加しないため、frontend PR #3 が期限後の再接続を扱う必要がある。省略された frontend Docker 認証ラッパーの代替は server PR #2 であり、この template 差分ではない。

scratch clone、ホストのみの試験、レビュー記録3件、各 PR 1コメントのみを使用した。grdm-dev の Docker 状態や runtime/.env は参照・変更せず、アプリの commit・push・merge・approve はしていない。
