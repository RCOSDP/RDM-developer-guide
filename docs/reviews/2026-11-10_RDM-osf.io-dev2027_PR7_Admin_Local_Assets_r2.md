### Verdict

**Changes requested — R2-01 (P2), `admin_tests/base/test_static_assets.py:21–24,62,68,83`.** The new decorator skips all seven filesystem checks whenever either package directory is absent. That matches the current CI checkout mount, but it also treats an accidentally missing package in an asset-enabled environment as an acceptable skip. There is no mandatory job in the inspected workflow that runs these seven assertions with packages present.

The six remaining cases provide real but partial coverage: no external base-template asset URLs, four required static-directory mappings, and the ionicons version/integrity declaration. The fix is therefore **not wholly uncovered**, but actual CSS/font availability and exclusion of package source/metadata are untested in the package-free job. In particular, adding `('vendor/ionicons', os.path.join(NODE_MODULES, 'ionicons'))` to `STATICFILES_DIRS` preserves all four membership assertions while publishing `package.json` and `src/ionicons.svg` when installed. The newly skipped exclusion checks would detect this; the six retained cases cannot. This is a source-derived counterexample, not a mutation test executed in this round.

Require an asset-enabled CI execution of all seven cases that fails if either package is absent, or add an equivalent mandatory artifact check. Local/package-free skipping may remain when explicitly selected. If CI changes remain out of scope, use package-independent fixtures to exercise publication boundaries and retain a separate mandatory check of real package files. Show that a missing package/file and an added package-root mapping make the required check fail.

### 判定

**要修正（changes requested）— R2-01（P2）、`admin_tests/base/test_static_assets.py:21–24,62,68,83`。** 新しいdecoratorは、どちらか一方のpackageディレクトリがないだけで実ファイル検査7件をすべてskipする。現行CIのcheckout mountには合うが、実アセットを検査すべき環境でpackageが誤って欠落した場合も正常なskipとして扱う。確認したworkflowには、package導入済みでこの7件を必ず実行するjobがない。

残る6件には有効だが部分的な検出力がある。base templateの外部asset URL禁止、必須static directory対応付け4件、ioniconsのversion/integrity宣言を確認する。したがって修正が**完全に無検査になるわけではない**が、実CSS/fontの存在とpackage source/metadataの非公開はpackageなしのjobで未検査になる。具体的には `STATICFILES_DIRS` に `('vendor/ionicons', os.path.join(NODE_MODULES, 'ionicons'))` を追加しても4件の包含assertionは成功する一方、導入済み環境では `package.json` と `src/ionicons.svg` が公開される。skipされた非公開検査はこれを検出できるが、残る6件では検出できない。これはソースから導いた反例であり、この回でmutation testを実行した結果ではない。

CIで実アセット導入済みの7件を必須実行し、どちらかのpackage欠落を失敗にするか、同等の必須成果物検査を追加すること。明示的に選んだローカル/packageなし環境ではskipを残してよい。CI変更を範囲外とするなら、packageに依存しないfixtureで公開範囲を検査し、実packageファイルの必須検査も別途維持すること。package/fileの欠落とpackage rootの追加公開を負の対照にして、必須検査が失敗する証拠を示してほしい。

### 根拠と限界

`gh api` compareで1ファイル28行追加の差分と、対象headの試験全文を確認した。文脈として `.github/workflows/unit-tests.yml`、`.github/scripts/ci/run-tests.sh`、CI Compose override、`docker-compose.yml`、Dockerfileを読んだ。CIはweb経由で実行し、checkoutを `/code` にmountしてroot node_modulesだけをvolumeで補うため、admin node_modulesは提供されない。adminサービスのvolumeはwebには適用されない。Dockerfileはadmin package導入とcollectstaticを行うが、このassertion群は実行せず、追加公開されたsource/metadataも拒否しない。イメージbuild成功は同等の検査にはならない。
