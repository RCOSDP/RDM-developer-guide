### Verdict

**Changes requested.** Reviewed exact head `10004e676099098944c66d0a54f51cdf34b97e50` against `2d1b5715`. R2-01 (paired server expiry) is closed by the independent socket probe against server `67aae1d7`. R2-02's authorization defect is fixed: superseded mappings do not issue tokens even when remote deletion fails, and a newer stored version causes the old room's renewal to return 404 without opening the new page. Cleanup retry still has a gap.

### R3-01 / P2 — retry a known pending deletion before rejecting its renewal

`addons/base/views.py:1241–1242` rejects a room already moved into `superseded:` before reaching `supersede_file_editor_docs` at line 1249. After a new version is saved, the first old-room renewal attempts DELETE, stores the pending marker on failure, and returns 404. If deletion becomes available again, every later old-room renewal still returns 404 but never attempts DELETE. When no one opens the new page or renews its current room, the retired persisted draft remains indefinitely. This contradicts the helper's promise to retry on every renewal.

An isolated probe executing seven actual function bodies observed one failed deletion, then **zero additional DELETE calls and one pending entry** after retrying the old room with deletion restored. Opening the new page did delete it; renewal of a current room also retries successfully. Keep the old-room 404, but route known pending rooms through cleanup after permission/file checks, or provide another reliable retry mechanism. Add a regression that restores deletion and repeats only the old-room request.

### Verified behavior and limits

`superseded:` entries are excluded from renewable IDs. The probe confirms no new token after a failed DELETE, a 404 on the first renewal after a new version exists without a page view, successful cleanup on a new page, and successful cleanup on current-room renewal. The save-related behavior is **renewal denial based on the stored latest version**. There is no save hook in this change: an established socket is closed by DELETE on the next applicable view/renewal, or by its token's expiry (default 600 seconds). The probe models the stored version using a dependency double; it is not a real WaterButler save.

### 判定

**changes requested（要修正）。** 正確なhead `10004e676099098944c66d0a54f51cdf34b97e50` を `2d1b5715` と比較した。R2-01（対応サーバーの期限失効）はサーバー `67aae1d7` への独立ソケット試験で解消。R2-02の認可問題も修正済み。遠隔削除が失敗しても置換済みの対応表からトークンは出ず、新版保存後は新版ページを開かなくても旧部屋の更新が404になる。ただし削除再試行には抜けが残る。

### R3-01 / P2 — 既知の削除待ち部屋は更新を拒否する前に削除を再試行する

`addons/base/views.py:1241–1242` は `superseded:` に移動済みの部屋を、1249行の `supersede_file_editor_docs` より前に拒否する。新版保存後の最初の旧部屋の更新ではDELETEを試み、失敗すると削除待ちを保存して404を返す。削除先が復旧しても、次からの旧部屋の更新は404だけでDELETEを試さない。誰も新版ページを開かず現行部屋も更新しなければ、退役した永続下書きが無期限に残る。これはヘルパーが説明する「更新要求ごとの再試行」と一致しない。

実際の7関数の本体を実行する分離試験で、1回の削除失敗後に削除先を復旧して旧部屋を再要求すると、**追加DELETE 0回、削除待ち1件** だった。新版ページを開くと削除でき、現行部屋の更新でも再試行は成功した。旧部屋の404は維持し、権限とファイルを検査した後で既知の削除待ち部屋を掃除へ通すか、別の確実な再試行手段を用意する必要がある。削除先復旧後に旧部屋だけを再要求する回帰試験を追加すること。

### 確認した挙動と限界

`superseded:` の項目は更新可能なIDから除外される。削除失敗後の新規トークン非発行、新版ページ未表示でも新しい保存済み版があれば最初の更新で404、新版表示時の掃除、現行部屋更新時の掃除を確認した。保存に関する挙動は **保存済みの最新版を基準にした更新拒否**。この変更には保存時の呼出し処理はなく、既存ソケットの切断は次の対象ページ表示・更新時のDELETE、またはトークン期限（既定600秒）で起きる。試験は保存済み版を代役で表しており、実際のWaterButler保存ではない。
