## English

### Verdict: request changes

Reviewed repository `RCOSDP/RDM-osf.io-dev2027`, PR #1, head `546969eb33f42e35be5dc5c5ac8bfe55e3ef0bbc`. This is a review recommendation, not a submitted approval or merge. ### Findings, ranked by severity

1. **R1 — Medium (P2): the new anonymous API 2.10 test supplies authentication.** At head, `api_tests/users/views/test_user_detail.py:260–262`, `test_social_values_old_version_not_logged_in` passes `auth=user_one` while expecting 401. The same test's 2.9 request at lines 256–258 omits authentication; successful authenticated requests at lines 234–248 use `user_one.auth`. Consequently the 2.10 case is not a clean test of absent credentials: rejection of the supplied authentication can satisfy the assertion, or helper handling can fail before the intended assertion. Remove the `auth` argument and run both versions' anonymous and authenticated cases. This defect originates in public commit `3243fd7`; preserve that history and add a follow-up fix. Runtime failure is not claimed: the test suite was not executed.
2. **R2 — Medium (P2): the stated integration order does not describe the actual topology.** PR body “内容” item 2 and merge commit body line 4 claim the SPEC-01 public → private → adopted-PR order. However the first parent is the already-private tip `3f4c9cd`, and the second is newer public tip `bacfe64`. [SPEC-01 §4 rule 3](../spec/01_manifest.md#4-rules) fixes the order. This is a private-seeded incremental public merge, not a literal execution of that recipe. The non-overlap makes the resulting content safe from a private/public conflict in this instance, but does not resolve the policy statement. Correct the PR explanation and record the owner's accepted bootstrap/incremental interpretation or exception in documentation; if strict reconstruction is required, propose it separately without rewriting or force-pushing upstream history. An additional commit can clarify the historical commit's assertion without amending it.
3. **R3 — Low (P3): a conversation-session URL is retained in metadata.** PR body line 14 and merge commit body line 8 (`Claude-Session`) contain a link to an individual AI session. It is not a private repository URL, and no access token or password was found in the inspected PR metadata/delta. The session's contents and access controls were not inspected, so it is not proven to expose secrets. The owner should decide whether this provenance link belongs in durable metadata; remove it from the editable PR body if unnecessary. Do not reproduce the URL in public review records or rewrite history merely to remove a non-secret reference.
